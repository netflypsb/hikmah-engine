# Hikmah Engine — Agent Integration Guide

This file tells any AI agent (Claude Code, Hermes, Codex, Gemini, or any other)
how to use the hikmah-engine CLI to build and maintain an Islamic literature LLM Wiki.

## Architecture

The engine implements Karpathy's LLM Wiki three-layer pattern:

1. **raw/** — Layer 1: Original source documents (immutable after ingestion)
2. **wiki/** — Layer 2: Agent-maintained wiki pages with cross-references
3. **AGENTS.md + rules/** — Layer 3: Operating rules and schema

The wiki is further organized into sub-layers:
- L2-1 Source reflection: `wiki/sources/<slug>.md`
- L2-2 Abstraction: `wiki/entities/`, `wiki/concepts/`
- L2-3 Per-domain analysis: `wiki/overviews/`, `wiki/contradictions/`
- L2-4 Global aggregation: `wiki/overview.md`, `wiki/contradiction.md`

## CLI Commands

```
python -m hikmah ingest <file>        # Ingest a source document into the wiki
python -m hikmah lint [--fix]         # Health-check (broken links, orphans, schema)
python -m hikmah graph                 # Rebuild knowledge graph + clusters
python -m hikmah query <question>      # Search the wiki by graph traversal + BM25
python -m hikmah cascade <page>        # Trigger cascading updates for a page
python -m hikmah discover <seed>       # Find unexpected connections (Memex)
python -m hikmah manifest               # Update MANIFEST.json
python -m hikmah rubric <file>          # Islamic scholarly validation (single page)
python -m hikmah rubric --all            # Islamic scholarly validation (all pages) processing audit trail
```

## Ingest Workflow

1. Place source document in `raw/` (markdown, PDF, or text)
2. Run `python -m hikmah ingest raw/<file>`
3. The engine:
   - Reads the document
   - Creates a source page (`wiki/sources/<slug>.md`)
   - Extracts entities and concepts (cascading update to existing pages)
   - Rebuilds the knowledge graph
   - Runs auto-validation (broken links, schema, missing tags)
   - Appends to `log.md`

## Islamic Scholarly Validation

The engine enforces Islamic source tier compliance:

### Tier 1 — Qur'an and Its Exegesis
- Tafsir Ibn Kathir (primary), Fi Zilal al-Qur'an (secondary)
- Other classical tafasir (al-Tabari, al-Qurtubi, al-Baghawi, al-Sa'di)

### Tier 2 — Hadith Collections (Sahih)
- Sahih al-Bukhari, Sahih Muslim, Sunan (Nasa'i, Abu Dawud, Tirmidhi, Ibn Majah)
- Muwatta Imam Malik, Riyad as-Salihin, Forty Hadith collections

### Tier 3 — Classical Scholars
- al-Ghazali, Ibn Taymiyyah, Ibn al-Qayyim, al-Nawawi, Ibn Rajab, al-Dhahabi

### Tier 4 — Contemporary Authenticated Scholars
- Ibn Baz, Ibn Uthaymeen, al-Albani, al-Qaradawi (fiqh only)

### Prohibited Sources
- Shi'a sources, non-Muslim orientalist sources for theology
- Weak/fabricated hadith without explicit labelling
- Unverified websites, anonymous blogs

## Page Schema

Every wiki page uses YAML frontmatter:

```yaml
---
title: "Page Title"
type: source | entity | concept | synthesis | overview | contradiction | timeline
tags: []
sources: []
last_updated: YYYY-MM-DD
---
```

Use `[[PageName]]` wikilinks for cross-references.

## Federation

The engine supports federated multi-wiki architecture:
- Each wiki (quran-wiki, fi-zilal-wiki, etc.) is a standalone directory
- Cross-wiki queries search all federated wikis
- Concept pages can span multiple wikis
- `wiki/meta/` contains cross-wiki bridges and syntheses

## Versioning

- v1.0 = manual curation (existing content, not regenerated by engine)
- v2.0 = first automated engine release
- MANIFEST.json tracks per-page provenance (which version curated each page)
